# Как поднять сайт ШТАТНО на своём хостинге

Инструкция для случая, когда доступа к платформе poehali.dev больше нет
или вы решили переехать. Здесь всё, что нужно, чтобы сайт заработал
с нуля.

Рассчитано на человека, который умеет заказать хостинг и скопировать
команду в консоль. Если что-то не получится — покажите эту страницу
любому системному администратору, ему хватит.

---

## Что вообще такое этот сайт

Три части, каждая может жить отдельно:

| Часть | Что делает | Куда ставить |
|---|---|---|
| **Витрина** | Страницы, которые видит покупатель | Любой хостинг статики |
| **Функции** | Приём заявок, админка, каталог | Сервер с Python |
| **База** | Товары, марки, заявки | PostgreSQL |

Плюс **фотографии** — около 1900 файлов, лежат отдельно.

Особенность: страницы товаров собраны заранее, в виде готовых файлов.
Поэтому витрина работает даже если функции и база лежат — покупатель
увидит каталог, но не сможет оформить заказ.

---

## Что понадобится от хостинга

**Минимум** (сайт работает, заказы принимаются):

- **Место на диске:** 1 ГБ. Сама витрина занимает 70 МБ, фотографии —
  около 300 МБ, остальное про запас.
- **PostgreSQL:** версия 12 или новее. База маленькая, 11 МБ.
- **Python:** версия 3.11. Нужен только для функций.
- **Node.js:** версия 20 или новее. Нужен только чтобы пересобирать
  сайт после правки товаров — на самом хостинге может не стоять.
- **Домен и SSL-сертификат.** Сертификат бесплатно даёт Let's Encrypt.

**Чего НЕ нужно:** мощного процессора, много памяти, отдельного
сервера. Подойдёт самый простой VPS за 300–500 рублей в месяц.
Витрину вообще можно положить на бесплатный хостинг статики.

| Файл | Что это |
|---|---|
| `database.sql` | Все данные: 1818 товаров, 66 марок, 14 категорий, 1387 связок проводки, статьи, инструкции, настройки |
| `images-list.txt` | Адреса всех 1923 фотографий |

| `РАЗВОРАЧИВАНИЕ.md` | Этот файл |

Код сайта — в этом же репозитории, папками выше.
Структура базы (какие таблицы) — в папке `db_migrations`.

**Чего здесь нет:** заказов покупателей, данных дилеров и паролей.
Это персональные данные, им не место в репозитории. Если нужны —
выгрузите отдельно из админки, пока доступ есть.

## Порядок действий

### Шаг 1. База данных

Создайте пустую базу и накатите структуру:

```bash
createdb shtatno
cd db_migrations
for f in V*.sql; do psql -d shtatno -f "$f"; done
```

Миграции применяются **по порядку номеров** — они так и названы:
`V0001__`, `V0002__` и дальше. Порядок важен.

Затем залейте данные:

```bash
psql -d shtatno -f backup/database.sql
```

Проверьте, что всё легло:

```bash
psql -d shtatno -c "SELECT COUNT(*) FROM products;"
```

Должно быть 1818.

**Про схему.** На платформе таблицы лежали в схеме
`t_p61203256_auto_catalog_site`, а не в обычной `public`. В дампе
названия схем убраны, так что данные лягут в схему по умолчанию.
Если хотите свою — создайте её и укажите в переменной
`MAIN_DB_SCHEMA` (см. шаг 3).

### Шаг 2. Фотографии

```bash
sh backup/download-photos.sh ./photos
```

Скачает около 1900 файлов, займёт несколько минут. Если оборвётся —
запустите ещё раз, уже скачанное пропустится.

Файлы разложатся по папкам так же, как в адресах. Раздайте папку
`photos` своим сервером и замените в базе начало адреса:

```sql
UPDATE products
   SET images = REPLACE(images::text,
       'https://cdn.poehali.dev/projects/e02f6838-189a-4b34-9b79-263263819d03/bucket/',
       'https://ваш-домен.ру/photos/')::jsonb;
```

**Осторожно, 23 фотографии лежат на чужом сервере** (`images-ru.ksize.ru`)
— это поставщик. Они могут пропасть в любой момент, и это не в вашей
власти. Стоит заранее перенести их к себе: в админке есть кнопка
«Перенести фото к нам» в разделе Сайт → Настройки.

### Шаг 3. Функции

Четыре функции в папке `backend`: `catalog`, `orders`, `admin`,
`dealers`. Каждая — один файл `index.py` с функцией `handler`.

Способ запуска зависит от хостинга. Самый простой — обернуть
во Flask и запустить как обычное веб-приложение:

```python
# server.py — кладём рядом с папкой backend
from flask import Flask, request, jsonify
import importlib.util, json, sys

app = Flask(__name__)

def load(name):
    spec = importlib.util.spec_from_file_location(
        name, f'backend/{name}/index.py')
    mod = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(mod)
    return mod.handler

HANDLERS = {n: load(n) for n in ('catalog', 'orders', 'admin', 'dealers')}

class Ctx:
    request_id = 'local'

@app.route('/<name>', methods=['GET', 'POST', 'PUT', 'DELETE', 'OPTIONS'])
def call(name):
    handler = HANDLERS.get(name)
    if not handler:
        return jsonify({'error': 'not found'}), 404
    event = {
        'httpMethod': request.method,
        'headers': dict(request.headers),
        'queryStringParameters': dict(request.args),
        'body': request.get_data(as_text=True),
    }
    res = handler(event, Ctx())
    return (res.get('body', ''), res.get('statusCode', 200),
            res.get('headers', {}))

if __name__ == '__main__':
    app.run(port=8000)
```

Запуск:

```bash
pip install flask psycopg2-binary boto3 openpyxl Pillow
python server.py
```

**Переменные окружения** — их нужно задать перед запуском:

| Переменная | Что это | Обязательна |
|---|---|---|
| `DATABASE_URL` | Адрес базы: `postgresql://user:pass@localhost/shtatno` | да |
| `MAIN_DB_SCHEMA` | Схема в базе, по умолчанию `public` | нет |
| `ADMIN_PASSWORD` | Пароль входа в админку | да |
| `AWS_ACCESS_KEY_ID` | Ключ хранилища для загрузки фото | только для загрузки новых фото |
| `AWS_SECRET_ACCESS_KEY` | Второй ключ хранилища | то же |

Без ключей хранилища сайт работает, но в админке не получится
загружать новые фотографии. Замените на любое S3-совместимое
хранилище или перепишите загрузку на сохранение в папку.

### Шаг 4. Витрина

Укажите адреса функций в файле `backend/func2url.json`:

```json
{
  "catalog": "https://ваш-домен.ру/api/catalog",
  "orders":  "https://ваш-домен.ру/api/orders",
  "admin":   "https://ваш-домен.ру/api/admin",
  "dealers": "https://ваш-домен.ру/api/dealers"
}
```

Соберите сайт:

```bash
npm install
npm run build
node scripts/prerender.mjs
```

Первая команда соберёт приложение в папку `dist`, вторая — создаст
готовые страницы всех товаров в папке `public`. Именно `public`
и нужно раздавать посетителям.

**Важно про пререндер.** Он собирает почти 2000 готовых страниц —
для каждого товара, категории, статьи. Благодаря этому поисковики
видят полноценные страницы с текстом, а не пустой каркас. Без него
сайт продолжит работать для людей, но выпадет из поиска. Не
отключайте его «для экономии места».

### Шаг 5. Настройка веб-сервера

Пример для nginx:

```nginx
server {
    listen 443 ssl;
    server_name ваш-домен.ру;

    ssl_certificate     /etc/letsencrypt/live/ваш-домен.ру/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/ваш-домен.ру/privkey.pem;

    root /var/www/shtatno/public;

    # Функции
    location /api/ {
        proxy_pass http://127.0.0.1:8000/;
        proxy_set_header Host $host;
    }

    # Фотографии
    location /photos/ {
        alias /var/www/shtatno/photos/;
        expires 30d;
    }

    # Готовые страницы: сначала ищем файл, потом папку с index.html,
    # и только в крайнем случае отдаём каркас приложения
    location / {
        try_files $uri $uri/index.html /index.html;
    }
}
```

Последняя строка — ключевая. Без неё готовые страницы товаров не
будут отдаваться, и поисковики увидят пустой сайт.

## Что проверить после переезда

1. Открывается главная, видны товары.
2. Открывается страница любого товара **по прямой ссылке** (не переходом
   с главной) — проверяет, что пререндер отдаётся.
3. Работает подбор по марке и модели.
4. Отправляется заявка — проверяет функции и базу.
5. Открывается админка по адресу `/admin`, пароль подходит.
6. В админке видны товары — проверяет доступ функций к базе.
7. Фотографии показываются, а не битые квадраты.

---

## Как обновлять товары после переезда

Правите в админке, потом пересобираете сайт:

```bash
npm run build && node scripts/prerender.mjs
```

Без пересборки правки видны в админке, но не на витрине — страницы
ведь готовые. Это плата за скорость и место в поиске.

Имеет смысл повесить пересборку на кнопку или запускать по расписанию,
скажем, раз в час.

## Частые грабли

**Страницы товаров отдают 404.** Не настроен `try_files` в nginx
(см. шаг 5) — сервер не ищет `index.html` внутри папки товара.

**Каталог пустой, товаров нет.** Функция `catalog` не достучалась до
базы. Проверьте `DATABASE_URL` и что схема указана верно.

**Фотографии не грузятся.** В базе остались старые адреса на
`cdn.poehali.dev`. Замените их запросом из шага 2.

**В админку не пускает.** Не задан `ADMIN_PASSWORD` или функция
`admin` не запущена.

**Сайт пропал из поиска через месяц.** Забыли про пререндер — либо
не запускаете `prerender.mjs` после сборки, либо nginx не отдаёт
готовые страницы.

## Сколько это стоит

Ориентир на 2026 год:

- VPS с Python и PostgreSQL: 300–600 ₽/мес
- Домен: 200–900 ₽/год
- SSL: бесплатно (Let's Encrypt)

Витрину можно положить и на бесплатный хостинг статики, оставив на
VPS только функции с базой — тогда выйдет ещё дешевле.
